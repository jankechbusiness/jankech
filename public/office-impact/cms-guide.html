Editor workflow

No code for everyday updates.

The website reads three simple content files. Pages CMS gives the organisation a friendly editor for those files, while GitHub remains the technical source of truth.

What happens after “Save”?

EditorSigns in to Pages CMS and changes content.
→
Pages CMSWrites the updated JSON or uploaded image into GitHub.
→
GitHubRecords the change and triggers the existing Pages deployment.
→
WebsiteLoads the new posts, events and people automatically.

What the editor does not touch

The organisation never needs to edit HTML, CSS, JavaScript, GitHub Actions or deployment settings. Those remain with the technical owner.

The root .pages.yml file defines exactly which fields the editor sees.

LinkedIn in this prototype

The LinkedIn section is intentionally curated rather than scraped. An editor pastes the URL of a useful post and adds a short website summary. This is reliable, free and keeps the organisation in control of what appears.

A true automatic LinkedIn feed would require a separate feed provider or API-based integration.
